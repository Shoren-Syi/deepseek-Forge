# Forge 施工节点

用户指定的 D 盘原方案开发路线到 P5，后续精简方案到 P3。以下 P6–P10 是本次用户要求推进到 P10 的交付拆分，未冒充原文已有阶段。用户后来的“简单、稳定、高效，不要过多防御和验证”优先于原方案中的独立治理、证据与统计平台设计。

| 节点 | 交付内容 |
| --- | --- |
| P0 | 上游版本固定、独立源码和 D 盘数据、原生执行入口 |
| P1 | 失败、取消、续接与用户修改保护，复用原生机制 |
| P2 | Git/LSP、最小修改、上下文提示、实际同题 Token 观察 |
| P3 | 原生模型选择、首轮规则路由、可调整执行预算、按模型用量与费用估算；浏览器预设工具接入 |
| P4 | 工作台、侧栏检查器、Diff、日志搜索与错误筛选、原生布局和快捷键 |
| P5 | 按会话选择 Browser、Desktop、Office、Skills/MCP，实际任务落盘 |
| P6 | MCP 服务随便携版交付，独立入口连接 D 盘任务目录 |
| P7 | 单一执行结构、按需工作区摘要与项目经验、原生历史检索，保留单一执行事实来源 |
| P8 | 针对本次改动的组合与真实任务检查 |
| P9 | Windows 便携构建与独立交付目录 |
| P10 | 使用说明、结果清单、剩余限制，完成后停止新增工作 |

后续按原方案功能清单补齐了轻量规则路由、可调整预算、分模型统计、单价估算、成本模拟和项目摘要/经验记录。使用原生设置、日志投影与项目 Markdown，不引入独立账本或协作调度。没有价格来源时费用显示未知，也不把单次样本的 Token 减少说成整体提速。实际交付和验证见完整功能交付记录.md。
