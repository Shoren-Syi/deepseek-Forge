# DeepSeek Forge 开发过程与功能边界

## 1. 项目来源与目标

Forge 从 DeepSeek Harness 独立拉取源码开始，在 D 盘建立单独副本。原有 DSH 不修改，Forge 使用自己的 Profile、应用标识、构建缓存、运行数据和便携目录。

目标是做一个 Windows 优先、编程任务优先的终端式 Agent 工作台：保留 Harness 原生执行循环、会话事件、权限、取消、恢复和用量投影，只在插件和 UI 层补足工程工作流。

用户随后明确了三个实现取舍：执行结构保持单一、界面要像终端而不是普通应用、执行过程不要把内部消息暴露到当前对话。所有后续设计都按这三个约束收敛。

## 2. 开发阶段

### P0：独立底座

- 固定上游版本、保留上游历史和许可证。
- 建立 Forge Profile、应用 ID 和 Windows 便携构建入口。
- 把缓存、临时文件、运行数据和构建产物放到 D 盘。
- 保留原生 Agent Loop、Session、Tool Registry、权限和取消机制。

完成判断是 Windows 能启动、输入任务、调用文件和终端工具、显示结果并停止执行。

### P1：编程体验

- 接入文件、Patch、rg、Git、TypeScript/JavaScript 语义导航和 Diff。
- 保留用户已有修改，不自动提交、还原或清空工作树。
- 让错误、停止、暂停、等待和完成分别显示。
- 支持重启后续接原生会话。

通过独立 Forge-Example 工作区完成过实际修改、金额规则修复和用户文件保留检查。

### P2：效率与上下文

- 工作区摘要按需写入 `.forge/WORKSPACE.md`。
- 经验记录按需写入 `.forge/MEMORY.md`，只记录已确认约束、决策和已验证修复。
- 复用原生历史检索、上下文压缩和长结果裁剪。
- 增加按模型的 Token、缓存、重试和切换统计。
- 做过一次同题样本对比：Forge 输入 Token 少于标准模式，但没有把单样本结果宣称为总体提速。

### P3：模型、预算和扩展

- 接入真实模型目录和模型选择。
- 安装 `dsh-thinking-effort-slide-bar` 1.5.5，支持 high、low 等供应商档位。
- 新会话首轮可按简单/复杂规则选择模型；手动选模优先，不覆盖全局默认。
- 支持步骤、Token 和费用估算预算；达到上限后暂停下一步，提高预算后继续。
- 支持按模型用量、单价估算和成本/成功率模拟器。
- 接入 Browser、Desktop、Office、Skills/MCP 预设。

### P4：工作台

- 上方工具区、下方对话区、右侧固定工作检查器。
- 工具区最多同时显示三个功能，文件、终端、辅助任务可以并列查看。
- 工具、对话和检查器各自滚动，窄屏时检查器收窄。
- 任务设置直接打开固定检查器；设置按钮调用原生设置命令。
- 辅助任务使用独立原生会话，结果只显示在辅助任务区域，不把内部请求写进主会话。
- 工具栏提供项目/会话、文件、终端、Diff、设置和辅助任务入口。

### P5–P7：能力和执行记录

- Browser：验证网页访问、数量读取和结果文件落盘。
- Desktop：验证记事本输入和文件保存。
- Office：验证 XLSX、DOCX、PPTX 生成、读取和渲染。
- MCP：随包提供官方文件系统 MCP，可重新绑定 D 盘目录。
- 保持一个原生会话事实源，不建立第二套执行数据库。

### P8–P10：检查、封装和交付

- 对三分屏、布局恢复、输入框、辅助任务、预算、用量和滑块做定向测试。
- 生成 Windows x64 便携目录和独立 ForgeData。
- 提供启动、打包、本地 MCP 连接和签名脚本。
- 记录使用说明、结果清单、限制和未完成事项。

## 3. 当前功能

### 执行与代码

单一 Agent Loop、文件读写、Patch、Git、rg、PowerShell 7、后台命令、LSP、Diff、取消、暂停、恢复和错误显示。

### 工作台

终端风格输入框、三个工具分屏、固定检查器、独立滚动、日志搜索、错误筛选、上下文占用、输出速度、模型选择和推理等级滑块。

### 辅助执行

工作区摘要和经验记录是独立任务；执行结果在工具区显示，主会话只保留用户自己的对话内容。

### 扩展能力

Browser、Desktop、Office、Skills/MCP 均按会话预设加载，开始执行后工具契约保持稳定。本地文件 MCP 随便携版交付，外部 MCP 通过原生设置连接。

### 交付物

- 源码：Forge 副本本身。
- 便携版：`D:/codex/2026-10-11/new-chat-2/outputs/Forge-Windows-P10/DeepSeek Forge.exe`。
- 本地 MCP 连接入口：`Connect-Local-Mcp.cmd`。
- 构建入口：`Build-Forge.cmd`、`Package-Forge.cmd`、`Start-Forge.cmd`。
- 签名入口：`forge/Sign-Forge.ps1`。

## 4. 验证记录

- 输入框定向测试：115 项通过。
- 三分屏、布局恢复和面板操作：针对性测试通过，实际刷新后仍保留三个面板。
- 设置、辅助任务、预算和用量：针对性测试通过。
- Browser、Desktop、Office、本地 MCP：完成过真实任务并检查结果文件。
- UI 实际检查：模型列表和滑块使用实色背景；速度与上下文统计位于模型选择左侧；上下文详情可打开；当前模型档位保持。

完整上游测试未全绿，失败集中在部分 Desktop 启动、账号桥接、技能目录、工作区变更快照、插件安装网络回退、旧布局断言和环境相关测试。该结果已记录，不能称为全仓库测试通过。

## 5. 明确没有实现的内容

以下不是遗漏，而是方案和用户取舍明确排除的内容：

- Guardian 控制器、证据数据库、风险矩阵和独立治理后台。
- 第二套会话数据库、独立成本账本和多 Agent 互审调度。
- 自动分类模型、每轮自动切换模型和向量记忆系统。
- 大规模统计评测平台和正式成功率结论。

以下内容属于外部条件，当前没有伪造完成：

- 第三方 MCP 的具体服务地址、账号和凭据需要用户自己提供。
- 正式代码签名需要证书、私钥密码和 Windows SDK；当前便携版未签名，但已提供签名脚本。
- 多平台发行需要 macOS/Linux 构建机和对应签名材料；当前交付目标是 Windows。
- Windows 沙箱的子进程管道限制属于宿主边界，Forge 没有绕过它。
- 性能和成本只有少量样本，不足以得出总体提速、降本或成功率结论。
- 桌面截图理解取决于所选模型是否支持图片输入。

## 6. 发布说明

当前公开代码应以 `forge/README.md`、本文档和 `forge/剩余工作记录.md` 为准。提交钩子在当前环境中无法完整运行，因为推送环境找不到 `pnpm`；此前定向构建和测试仍保留各自日志。正式发布前，应在安装 pnpm 11.28.5 的环境中重新运行 typecheck、构建和打包，再使用组织证书签名。
